# 04 界面数据与报告规范

目标：左侧计划与右侧结果身份一致；卡片、曲线、表格、摘要和导出读同一份数据。
[返回总纲](README.md)。

## 1. 六项导航的数据责任

| 页面 | 数据来源 | 可执行操作 | 禁止的隐含操作 |
|---|---|---|---|
| 智能测试 | 对话/草稿、冻结计划、选中任务快照、统一报告视图 | 预览/修改计划、明确提交、请求取消、选择结果来源 | 消息发送或刷新自动运行 |
| 基准任务 | 固定用例目录、白名单请求 | 选择单项、标准套件或受限子集 | 修改底层算法与容差 |
| 运行记录 | 只读归档索引、活动任务快照 | 筛选、查看、回放 | 打开记录时重跑或改写旧数据 |
| 测试报告 | report_id 对应的统一报告视图 | 查看标签、定位证据、请求导出 | 以模型说明替代原始结论 |
| 配置管理 | 版本清单、C0、参数快照及实际生效参数 | 只读查看；选择允许的执行保护项 | 编辑固定 dt/摩擦/求解容差 |
| 系统设置 | 环境检查快照、执行占用、模型网关状态 | 明确触发检查、查看状态 | 未检查时展示假 GPU 或假模型连接 |

顶栏固定工作区 D:\benchagent；GPU/CUDA 信息缺失时显示“待载入”，
已有检查信息附时间和来源，不继承参考图环境。
场景图是标注的示意或有真实来源的静态素材，不承诺实时仿真视频。

## 2. 工作台五种展示模式

| 模式 | 右侧内容 | 状态与来源 |
|---|---|---|
| empty | 空指标和缺项说明 | 未执行，结果为 null |
| plan_preview | 目标帧数、固定配置和计划 | 未提交，不产生真实运行目录 |
| live | 绑定 job/case 的阶段、确认帧、日志和可用观测 | 实时，最终结论尚未产生 |
| archive | 已选旧任务/报告的只读数据 | 历史回放，注明是否沿用旧判定 |
| synthetic | 带明显水印的合成样例 | 不是真实任务，不生成性能结论 |

设计稿默认展示 synthetic 便于审阅；正式应用默认 empty。
合成演示须显式进入，不能提交真实执行或保存为真实 PASS 报告。
模式切换不能偷偷启动进程。新计划不得延用旧结果的完成标志。
在 live 阶段即使帧数达到目标，也应显示“待校验/报告生成中”，不能提前通过。

## 3. 单一指标字典

现有报告键保持兼容；新增均值放入目标视图模型，不回写旧报告。

| 中文指标 | 现有字段/来源 | 统一计算 | 单位 |
|---|---|---|---|
| 实际帧数 | actual_frames / 连续完整帧记录 | 直接读取 | 帧 |
| 物理步总耗时 | solver_time_total_s / step_ms | sum(step_ms)/1000 | 秒 |
| 平均每帧耗时 | solver_time_mean_ms_per_frame | sum(step_ms)/actual_frames | 毫秒/帧 |
| 平均牛顿迭代 | newton_iterations_mean_per_frame | newton_iterations_total/actual_frames | 次/帧 |
| 平均 PCG 迭代（主卡） | pcg_iterations_total_from_csv | 聚合总次数/actual_frames；视图字段 pcg_mean_per_frame | 次/帧 |
| 每次 PCG 求解平均（详细报告） | pcg_iterations_total_from_csv、pcg_solves | 聚合总次数/pcg_solves；视图字段 pcg_mean_per_solve | 次/求解 |
| 牛顿迭代总次数 | newton_iterations_total | 帧记录中的牛顿计数求和 | 次 |
| PCG 迭代总次数 | pcg_iterations_total_from_csv | 帧记录中的 PCG 聚合计数求和 | 次 |
| 已记录 PCG 明细次数 | pcg_iterations_total_from_stats | 实际存在的明细计数求和 | 次 |
| PCG 明细覆盖率 | pcg_iterations_coverage | 有明细的调用数/总调用数 | % |
| 累计碰撞对计数 | collision_counter_total | collision_summary 原始计数 | 次（源码口径） |
| 最大碰撞对数 | collision_pair_max | collision_summary 原始最大值 | 对 |
| 进程墙钟耗时 | wall_time_s | 运行器的单调时钟差 | 秒 |

分母为 0 或缺失时为 null，显示“未采集”；不能除零或替换为 0。
数值在底层保持精度，展示层统一舍入；导出记录舍入策略。
主卡、关键帧和曲线可采用不同展示精度，但不能从已舍入值重算总量。

重要口径：

- V3.1 主卡 PCG 为次/帧；旧 V3 的次/求解主卡决定不再使用。
- PCG 求解调用数和牛顿计数各自读取，不强行由另一个数组长度推导。
- Graph/kernel 启动次数不是 PCG 迭代数。
- 物理步耗时是现有同步墙钟范围，包含首次 Graph 准备，排除初始化/导出/渲染；
  不混称为旧 timeCost.txt 的 CUDA Event 时间。

- 累计碰撞对计数不是去重碰撞事件，也不是碰撞检测函数调用次数。

## 4. 单项与任务集

六项主卡、双曲线和关键帧表绑定同一个选中 case_id，不能把多用例均值简单平均。
标准套件结果以用例表并列展示；默认选中最长的已有有效用例，没有有效用例则显示原因。
如果后续提供任务集整体指标，必须另行标“任务集整体”，用总量与对应总分母计算。

“校验通过任务数”以所选任务数为分母，包含失败/跳过/取消的用例。
任务集原始状态仍按确定性汇总规则：

- 三项或所选子集全部通过才 PASS。
- 一部分通过为 PARTIAL。
- 全部跳过为 SKIPPED。
- 无通过且至少一个失败为 FAIL。
- 任务仍在进行时按未完成状态展示，不提前宣布整套通过。

自定义子集的完成标准是所选集合，不照搬当前只针对固定三项的 suite_status 长度判断。
此调整必须在应用服务/汇总器实现并测试，不能只在 UI 改文字。

## 5. 曲线、关键帧和日志

### 曲线

耗时曲线横轴帧序号、纵轴毫秒；迭代曲线横轴帧序号、纵轴次/帧。
牛顿与 PCG 保持稳定颜色并配中文图例。
曲线只取实际存在且类型合法的帧数据；缺帧不插值成真实数据，不用零填补。
实时观测与最终归档数据由来源字段区分，最终报告以已落盘统计为准。
原型合成曲线不能作为真实初始性能样本。

### 关键帧

按实际采集序列选择首帧、分位位置和末帧，展示确切帧号。
若采用固定目标帧位置，未到达的行必须显示未采集，不以邻近帧冒充。
目标帧数与实际采集帧数同时保留，失败任务不得伪装完整采样。

逐帧碰撞对计数现有正式证据不提供时，表格为“未记录”。
不能把累计值平均分摊、由累计差猜测或用合成值填入真实报告。

### 日志

stdout/stderr 分流、带来源与游标；支持尾部跟随和暂停跟随。
暂停跟随不暂停仿真。游标处理字节偏移和编码边界，不能因换行不完整丢失正文。
示例日志必须保留合成标识，不能加入看似真实的 INFO 完成记录而不标来源。
界面截断仅影响展示，原始日志文件完整保留。

## 6. 结论与逐项检查

保留 [既有检查编号与规则](../逐项校验清单说明.md)：P00、V01–V12，接口异常时 E00。
整体状态与检查状态分别展示；检查可为 WARNING，整体任务仍可 PASS。
历史记录没有 checks 时显示“未记录”，不根据曲线补判通过。

分析结论采用确定性模板，例如“运行与统计证据校验通过”。
没有预定义性能门槛或参考数据时，不输出“性能良好/达到预期”等判断。
有限数值、无日志错误不等于严格无穿透或精度认证。
后期模型解释另设区域，标为附加解释，不覆盖原始结论。

## 7. 报告和归档结构

报告四标签：概览、运行配置、详细指标与检查、日志与异常。
同一数据对象驱动聊天摘要、工作台、报告和导出，避免多个地方重复计算。

当前使用cases任务集结构；任务状态和事件集中于data/planning/state.json，下列独立状态/事件及exports为后续规划：

~~~text
runs/<job_id>/
├── job_state.json
├── events.jsonl
├── plan.json
├── benchmark_summary.json / benchmark_summary.md
├── cases/<case_id>/
│   ├── plan.json / profile.json / inputs/
│   ├── run_meta.json / identity_before.json / identity_after.json
│   ├── stdout.log / stderr.log
│   ├── raw/
│   │   ├── metadata.json / status.json / collision_summary.json
│   │   ├── frames.csv / pcg_iterations.jsonl
│   │   └── 其他实际生成的状态证据
│   └── metrics.json / report.json / report.md
└── exports/
~~~

既有单项根目录和旧套件直接子目录由仓库适配读取，不迁移或改写原件。
raw/ 启动前不能创建，由原生 benchmark 生成。
检查表中的证据路径相对单项报告根目录解析；套件导出保留 cases/<case_id>/ 层级，不能平铺同名日志和统计文件。
旧报告沿用其记录时的状态；使用新版规则重验属于另一种明确操作，
不得在“查看”或“导出”过程中隐式发生。

## 8. 导出契约

| 格式 | 内容 | 规则 |
|---|---|---|
| Markdown | 中文结论、指标、检查及证据引用 | 复用统一视图和已有渲染基础 |
| JSON | 原始机器字段与来源/版本信息 | 原始报告原样保留；派生视图另标 schema 版本 |
| CSV | 中文列头、单位、逐帧实际值 | 未采集数值为空，原因和列映射写入导出清单 |
| PDF | 与同一视图对应的中文报告 | 字体、分页、单位与表格需渲染验收后启用 |
| ZIP | 报告、日志、指标及证据索引 | 只包含允许的任务文件；不包含凭据或任意目录 |

导出生成到受控 exports/，返回 artifact_id、相对路径、格式、SHA256、来源报告摘要。
同一来源报告、视图版本、语言和格式可复用导出；源摘要变化不能返回旧文件冒充新导出。
对旧归档生成新格式时保存为附加导出，不覆盖原始 JSON/Markdown。
未完成某种导出前按钮明确禁用，不能把 HTML/文本重命名成 PDF。

## 9. 页面布局与视觉验收

以最新 [V3.1 原型](../design/benchagent-v3-1-prototype.html) 为外观依据，
不恢复独立首页优先的旧布局。
桌面优先检查 1536×1024、1440 宽和 1280 宽，窄屏改为纵向布局；
宽表允许局部横向滚动，不缩小到不可读字号。
状态以文字、来源标识和样式共同表达，不只依靠绿色或紫色。
