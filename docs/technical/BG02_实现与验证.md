# BG02 草稿计划与真实集成验证

BG-02 库层已实现对话草稿、版本检查、冻结执行快照和幂等确认。109 项 Python 测试通过。
用户本轮允许推进实验后，已完成一次真实 20 帧预验证和一套 20/50/100 帧标准验证，共 4 次进程、190 帧，均通过既有检查。

## 模块与调用

| 文件 | 职责 |
|---|---|
| benchagent/planning_store.py | 元数据原子持久化、独占写锁、服务错误码 |
| benchagent/conversation_service.py | 对话、消息、草稿修订、严格规则解析、请求白名单校验 |
| benchagent/plan_service.py | 实际文件身份校验、冻结快照、摘要、明确确认及过期检查 |
| tests/test_planning_services.py | 23 项隔离测试，模拟进程和网络均不允许被服务调用 |
| scripts/run_bg02_validation.py | 本轮已授权真实验证入口，先预验证再套件，保存独立协议与证据 |

~~~python
from benchagent.planning_store import PlanningStore
from benchagent.conversation_service import ConversationService
from benchagent.plan_service import PlanService

store = PlanningStore()
conversations = ConversationService(store)
plans = PlanService(store)
conversation = conversations.create_conversation()
draft = conversations.update_draft(
    conversation["conversation_id"], "默认场景运行20帧", expected_revision=0)
plan = plans.preview_plan(draft["draft_id"], expected_revision=draft["revision"])
# 以下仅在明确确认操作后调用；仍不会创建任务或启动仿真。
receipt = plans.confirm_plan(plan["plan_id"], plan["plan_digest"], "unique-confirmation-request")
~~~

规则入口完整匹配请求，拒绝追加的改参或命令语句；标准模式及表单支持白名单非空子集，并按 20/50/100 排序。
消息中的规则回复标记为 rule，不伪装为模型回复。真实模型仍未接入。

## 冻结与确认边界

预览检查实际源码、资产、EXE/DLL 和固定配置与清单一致，再将请求、文件哈希、C0 参数、环境策略和超时冻结到 execution_snapshot。
摘要使用键排序、紧凑 UTF-8 JSON 和 SHA256，排除显示时间及计划标识。
修改草稿后新确认返回 PLAN_STALE；预览后文件变化同样使计划过期。
原计划保持不变，返回对象的修改不会写回存储。

同一确认请求重复调用返回同一收据；同一请求改绑计划返回 REQUEST_CONFLICT。
确认只写 CONFIRMED_NOT_SUBMITTED，job_id 为空。异步排队、执行提交幂等和取消仍由 BG-03 实现。
旧确认收据可重读，但再次用于实际提交前必须重新核验；修改草稿不会伪装成仍可执行的旧计划。
服务方法均不调用运行器、GPU 查询或网络，也不创建 runs 目录。

## 持久化决定

产品元数据当前集中在 data/planning/state.json，含 conversations、drafts、plans、confirmations 和确认请求索引。
一次更新使用同一份原子替换，避免确认对象与索引分别落盘造成半登记；对象通过标识关联。
写入使用 .write.lock 独占锁。并发冲突返回 SERVICE_BUSY 或 DRAFT_CONFLICT，调用方重读重试。
异常写盘不返回确认成功；损坏状态不覆盖，进程崩溃遗留锁不自动抢占。
此前规划的逐对象目录暂不落地，BG-03 如需迁移须保留标识与摘要。
