# 05 模型接口预留

本阶段模型处于待接入状态；此规范不会新增任何在线调用。
[返回总纲](README.md)。

## 1. 当前已有与后期开发

| 部分 | 当前情况 | 后续工作 |
|---|---|---|
| model_gateway/contracts.py | 已有供应商无关 dataclass 和 Protocol | 与应用服务绑定，不扩张为自由工具调用 |
| model_gateway/disabled.py | 已有默认禁用实现 | 正式 UI 默认使用 |
| configs/model_gateway.example.json | 已有无密钥示例 | 后期实现配置加载、校验和真实适配器选择 |
| planner.py 可选 LLM 分支 | 旧实验性直接调用 | 迁移/隔离，不作为新工作台的默认模型通路 |
| 提供商、型号、凭据、在线重试 | 尚未纳入正式接入 | BG-08 后期实施并独立验收 |

现有示例配置中的 enabled 是预留字段；本阶段不因为修改它就宣称已有真实 provider。
默认工厂返回 DisabledGateway，不能在缺模型时偷偷加载另一家服务。

参考图中的模型名称和“已连接”不是当前实现状态，也不自动确定技术供应商。

## 2. 当前协议

契约参考：[model_gateway_v1.json](../contracts/model_gateway_v1.json)。

| 类型/方法 | 字段或返回 |
|---|---|
| GatewayStatus | enabled、ready、provider、capabilities、message、schema_version |
| PlanRequest | request_id、user_text、locale |
| ExplainRequest | request_id、report_id、evidence_summary、locale |
| ModelResult | request_id、status、message、error_code、proposed_plan、explanation、schema_version |
| get_status() | GatewayStatus |
| propose_plan(request) | ModelResult |
| explain_report(request) | ModelResult |

ModelResult.status 为 disabled/ok/error，不是 PASS/FAIL。
模型结果没有覆盖验证器状态的合法字段。

默认禁用返回：enabled=false、ready=false、provider=disabled、capabilities 为空；
请求返回 MODEL_NOT_CONFIGURED，候选计划与解释均为空。
不读凭据、不导入在线 SDK、不发起网络请求、不触发仿真。
这些是已有占位的行为，不是“模型已可使用”。

## 3. 候选计划的后续通路

~~~text
用户输入
→ 应用服务登记 request_id 和草稿 revision
→ 规则解析器 或 后期模型网关
→ 候选意图 Schema 校验
→ 应用服务补入固定 backend 与身份
→ task-request-v1 校验
→ 冻结计划预览
→ 用户明确开始执行
→ submit_plan
~~~

后期新增候选意图只允许 mode、scene、task_frames、timeout_sec。
模型不能提供命令、任意本地路径、EXE 位置、配置覆盖、状态结论或未经允许的场景。
后端固定身份、关联 ID、文件哈希与环境策略由服务生成，不采信模型自报。

规则模式与模型模式最终必须经过同一个计划验证入口。
模型生成计划不能直接成为运行命令，成功回复也不等于提交。
request_id 在服务端绑定草稿版本；过期回复丢弃或作为旧消息留存，不能覆盖更新后的草稿。

候选意图 Schema 属于 BG-08 待实现项；本轮不修改当前 PlanRequest/ModelResult 代码。

## 4. 报告解释的后续通路

输入只允许来自统一报告视图的白名单摘要：
报告标识、原始结果状态、已验证的指标/单位、缺项标识、检查摘要及允许的证据引用。
默认不发送二进制状态、网格、完整目录、密钥或整份任意日志。
日志如有必要，后期增加明确的选择、截断和脱敏策略，作为数据处理契约验收。

输出是附加解释，须标识来源、模型、生成时间、输入摘要指纹。
解释与原始报告分开保存，不改 report.json 的指标、checks、errors 或 status。
UI 可以展示“模型解释不可用”，但不能因此删除确定性报告、重跑仿真或改变结论。
模型给出的数字或推断不自动写回指标卡，也不作为数值正确性的证明。

## 5. 配置与凭据

- 当前设置页只显示待接入状态，连接检查按钮禁用。
- 后期配置包括 provider、model、base_url、凭据环境变量名、超时及允许能力。
- 实际凭据只由模型适配器按受控配置读取；不放入浏览器会话、任务计划、命令、报告或普通日志。
- 日志中只保留请求标识、响应状态与必要计费元信息，不记录完整认证头。
- 不锁定某家提供商或默认向未知地址发送数据；真实配置是后期独立工作。
- 模型模块不得获得 job_manager 的执行接口或进程句柄。

## 6. 后期错误语义

| 错误 | 含义 | 核心流程 |
|---|---|---|
| MODEL_NOT_CONFIGURED | 当前已有的禁用结果 | 引导使用规则/表单计划，保留报告 |
| MODEL_TIMEOUT（拟新增） | 模型请求超时 | 不创建任务，不重跑仿真 |
| MODEL_REFUSED（拟新增） | 拒绝或不可处理 | 显示原因，不自动换计划 |
| MODEL_RESPONSE_INVALID（拟新增） | 结构或白名单不符 | 不进入提交 |
| MODEL_PROVIDER_ERROR（拟新增） | 服务或配置错误 | 保留确定性结果，附加模型错误说明 |

模型请求由独立的受控异步调用处理，不占用仿真执行租约、不阻塞页面，也不混入物理步计时。
模型请求重试只属于模型请求，不复用执行提交动作。
取消、重试、过期回复都必须通过原 request_id 和对象版本对账。

## 7. 当前与后期验收

当前可离线验证：默认禁用状态、请求标识回传、候选计划为空、输入报告不变、
无凭据读取和无网络请求。
真实 provider 的协议适配、结构化返回、鉴权、超时和在线行为都留到 BG-08。
真实模型验收不混入 GPU 基准计时，不改变已有确定性规则。
