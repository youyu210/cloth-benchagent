## 3. 页面与产品定位

一级导航固定为：智能测试、基准任务、运行记录、测试报告、配置管理、系统设置。

智能测试默认采用左侧对话/计划、右侧执行/分析的同屏布局。
对话负责表达需求和查看计划；确定性执行服务负责产生任务及结果。
原型中“开始执行”等真实动作处于禁用状态；后续接入须按任务服务规范实现。

## 5. 规范性原则

1. 一次确认绑定一个不可变计划；修改草稿不会改变已启动任务。
2. 对话、计划、任务、报告必须按标识关联，不能把旧成绩挂到新计划。
3. 单一执行入口与统一串行锁约束全部子任务，UI 不能直接启动进程。
4. 指标只在统一结果层计算，界面和导出读取相同的数据。
5. 生命周期与校验结论分开；完成进度不等于通过验证。
6. 合成、未执行、实时、历史回放明确分源，缺失值不补零。
7. 模型只能提供候选计划或附加解释，不能执行任意命令或改写验证状态。
8. 历史记录兼容读取；新增字段不回填为假数据。
