# 01 架构与模块设计

本文件规定目标架构和迁移边界；未标“已有”或“BG-01/BG-02/BG-03/BG-04/BG-05 已实现”的模块均为拟新增。
[返回总纲](README.md)。

## 1. 总体结构

~~~mermaid
flowchart TD
    UI["六导航界面 / 智能测试工作台"] --> APP["应用服务 AppService"]
    APP --> CONV["对话与草稿服务"]
    CONV --> PLAN["受限计划服务"]
    APP --> JOB["任务管理器 / 单串行工作器"]
    JOB --> RUN["仿真运行器"]
    RUN --> RAW["原始证据"]
    RAW --> PARSE["解析器"]
    PARSE --> VALIDATE["确定性验证器"]
    VALIDATE --> REPORT["报告写入"]
    APP --> REPO["只读归档仓库"]
    REPO --> VIEW["统一结果视图与中文展示"]
    REPORT --> REPO
    VIEW --> UI
    VIEW --> EXPORT["Markdown / JSON / CSV / PDF / 证据包"]
    CONV -. "后期候选计划" .-> MODEL["模型网关：当前 Disabled"]
    VIEW -. "后期证据摘要解释" .-> MODEL
~~~

没有 UI→Popen、模型→运行器、模型→验证器状态写入的通路。
模型当前禁用时，表单/规则计划、执行服务和报告链路应当独立完整。

## 2. 模块职责与迁移

| 模块 | 当前基础 | 目标职责 | 不承担的职责 |
|---|---|---|---|
| ui.py、ui_app.py（BG-04已实现） | 六导航与同屏工作台 | 导航、展示、提交明确操作、查询快照 | 拼接命令、管理进程、计算业务指标 |
| app_service.py（BG-04已实现） | main.py、runner.execute 的编排逻辑 | 统一应用入口、受限请求、关联校验 | 求解、自由工具调用 |
| conversation_service.py（BG-02 已实现） | planner.py 的规则入口 | 消息、草稿来源、候选计划及版本 | 因为发送消息而直接运行 |
| plan_service.py（BG-02 已实现） | validate_plan 与请求 Schema | 校验白名单、冻结计划、确认及摘要哈希 | 接受任意物理参数 |
| archive_repository.py（BG-01 已实现） | 当前运行目录和报告 | 只读索引、兼容旧格式、定位证据 | 改写历史判定、自动重跑 |
| view_models.py（BG-01 已实现） | parser、presentation | 统一指标、来源、选中用例、缺项解释 | 凭 UI 状态猜测结果 |
| job_manager.py（BG-03 已实现） | runner.execute | 工作器、队列、生命周期、取消、锁所有权 | 多个 UI 会话各自重复执行 |
| progress_reader.py（BG-05已实现） | 每帧 flush 的 frames.csv | 连续完整帧、阶段事件、日志增量快照 | 提前作最终 PASS/FAIL |
| runner.py | 已接入BG-03取消及进程树监督 | 子进程所有权、隔离环境、证据归档 | 调用 Streamlit UI |
| parser.py | 已有严格解析器 | 最终统计解析和合法性验证 | 将缺失值默认为零 |
| validator.py、checks.py | 已有确定性验证 | 整体结论及逐项检查 | 基于模型措辞修改结论 |
| reporter.py、presentation.py | 已有中文报告和表格 | 保留底层格式，复用统一视图渲染 | 每种导出独立发明计算口径 |
| export_service.py（BG-06已实现） | 当前 Markdown/JSON 和界面 ZIP | 受控导出、中文排版、产物清单 | 接受任意本地路径 |
| model_gateway/ | 已有 Protocol 和禁用实现 | 后期供应商适配和结果封装 | 启动程序或写入验证结论 |

新增 view_models 不要求删除原解析器；先通过适配器复用其指标，再逐步把重复计算集中。
当前仅有总计的指标不得为了填满原型表格而虚构逐帧数据。

## 3. 服务与 UI 的进程边界

- 正式首版仍为本地 Python 应用；UI 调用 Python 服务，不新增必须部署的 HTTP 服务。
- 同一个 UI 服务实例只创建一个任务管理器与一个串行工作器；页面重绘只复用服务。
- 后台工作器不调用 st.*，只更新持久化任务快照和事件。
- UI 轮询快照，不等待一次完整仿真阻塞返回，不以 session_state 作为执行事实来源。
- 旧 CLI 必须保留。迁移后通过适配器复用同一执行内核和跨进程锁；重复的独立 CLI 命令仍是独立用户操作。
- 无论 UI 与 CLI 是否同进程，共用执行锁都必须保证同一工作区最多一个活动仿真进程。
- 多任务集的子任务串行执行；同一任务集只获取一次执行租约，不嵌套当前 exclusive()。

├── configs\                      # 固定配置和模型禁用示例
├── docs\technical\               # 当前技术规范
├── runs\                         # 已有与未来运行证据

data/ 只保存产品元数据，不能代替 runs/ 中的证据。
归档索引是可重建缓存；单项记录和原始证据才是事实来源。
